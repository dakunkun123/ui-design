# V30 · 江湖志首屏，从插图卡片到可交互山水

## 本次范围
用户最新截图定位在「山河故卷」精选首屏。此次重构该首屏，不替换下方三篇入口、阅读器、收藏数据、剑录与旧版 V29 生长系统。历史问题不是本轮已全部解决的承诺。

## 证据与原因
1. App.jsx 原先 featuredIndex 只改变标题/简介，SpatialScene kind="journal" 永远展示同一套人物、山水与枫枝；「藏锋」与画面主体没有语义联系。
2. 巨大半身人物没有落脚点，头顶和衣襟用雾直接截断；它是海报人物的比例，背景却是远景山水，透视尺度不一致。
3. 标题在景外，正文在固定右栏，背景在矩形盒内；三者构图、运动和操作状态分离，形成 PPT 双栏感。
4. 鼠标的反馈没有清楚的原因和后果；整图缩放或漂移不能代替枝叶、羽翼、流水各自的运动。

## 参考研究（实际观察与推断分开）
- https://2019.makemepulse.com/：浏览器操作 START、草地拖动、NEXT。拖动后茎沿输入位置发展，花叶稍后成熟并留在场景；前景植物包围视野、小人物与地面比例一致，进入水边后晶石/瀑布和构图共同改变。参考也使用纸片文字框，可见问题不是“任何框都不能有”，而是空间、材质和动作是否统一。
- https://string-tune.fiddle.digital/：首次媒体未就绪，随后正常加载。实际观察到首页大字与斜剑互相遮挡，向下滚动约 4–14% 时剑/鞘分离、位置旋转、文字逐段由模糊到清晰。提取的是同一个输入进度同时驱动物体与文字，不推断其私有实现，也不声称逐一体验全站所有页面。
- video-1：226 帧 / 30fps / 7.533 秒；16 个带时间戳均匀样本。树干不变，苔藓沿真实表面逐渐覆盖；生长有依附和方向。
- video-2：485 帧 / 30fps / 16.167 秒；16 个带时间戳均匀样本。头盔/面罩变化围绕稳定面部锚点，而非整张图平移。资料见同目录 contact sheet 与 metadata。此为时间采样分析，不称为逐帧全部审阅。

## 设计与实施计划
1. 三个真实场景：断崖行者 / 江上轻舟 / 石上藏锋。每个独立透明素材，有地面或水面锚点，人物尺寸回到环境尺度。
2. 统一空间：景深山水 → 大幅书法字 → 近景实物 → 局部风/羽翼/水纹 → 必要操作。顶部缩小卷名，删除旧的大空白和固定右栏。
3. 连贯输入：鼠标位置提供小幅视差；按住拖动产生风势，作用于近处落叶、字的轻微偏移和鹤飞速度；松开有惯性但不产生整图弹回。提供按钮替代拖拽。
4. 场景切换：GSAP 同一时间线协调离场、景物露出、文字分字显现。三个主题的方向/构图不同，不再只换一句话或重复整图放大。快速点击可中断并以最终选择为准。
5. 不增加无必要依赖；沿用 GSAP、Three.js 与 Canvas2D。新模块独立命名，保留旧版资产与功能。
6. 生命周期：视口外、后台、阅读器/菜单打开时停更新；静观模式、系统减少动态可用；鼠标取消/窗口失焦释放按住状态。

## 验收
- 构建与自动化模型测试；三场景图片均成功加载、透明边缘无黑底。
- 浏览器实测选择三篇、连续快速切换、按住拖拽、按钮替代、暂停和恢复、读此篇对应正确文章、关闭后恢复。
- PC 1280 与 1920 视口检查标题/主体/底栏、无遮挡或横向溢出。
- 保留搜索、书签、三个下方入口与阅读器功能；保存截图和检验记录。

## 非本轮承诺
这是实时 2.5D 绘画场景，不冒充全骨骼人物动画、物理流体或完整布料仿真。下一阶段可以针对已认可构图，把角色衣摆/蓑衣/剑穗做独立骨骼分层，而不是继续堆叠全屏特效。
